# Extract PDF Pages — المرحلة الأولى

## النطاق

اقتصر التعديل على `extract-pdf-pages` داخل `pdf-engine.ts` وربطه بفرع مستقل في `ToolWorkspace.tsx`. لم يتغير OCR أو QR أو PDF→Word أو `pdfToImages` أو Lifecycle. بقيت الأداة `Disabled`.

## التغيير

أضيفت `extractPdfPages(file, pages, report)` بدل اعتماد هذا slug على الفرع العام `alterPdf`. تقرأ الدالة PDF محليًا، وتتحقق من `%PDF-`، وتحافظ `parsePageList` على ترتيب المستخدم بما في ذلك الطلب غير المتتالي. تنشئ PDF جديدًا بـ`copyPages`، ثم تعيد فتح المصدر والمخرج بـPDF.js للتحقق من:

| التحقق | السلوك |
|---|---|
| عدد الصفحات | يساوي عدد الصفحات المطلوبة |
| ترتيب المحتوى | أبعاد كل صفحة تطابق الأصل المطلوب، والنص المستخرج يطابق الصفحة الأصلية عندما يوجد نص |
| الملف المعطوب | رسالة عربية صريحة بلا تنزيل أو ادعاء نجاح |
| الملف المحمي | رسالة حماية صريحة بلا تجاوز كلمة مرور |
| غير PDF | رفض magic bytes قبل التحليل |

النتيجة تعرض الصفحات المطلوبة وعددها والتحقق من ترتيبها، من دون استخدام `pdfToImages` أو Canvas.

## قبول المتصفح الفعلي

| العينة | الطلب | النتيجة |
|---|---|---|
| English PDF | `1` | صفحة واحدة؛ الترتيب صحيح؛ المصدر لم يتغير |
| PDF عربي Unicode | `2,1` | صفحتان بترتيب غير متتالٍ صحيح؛ تم التحقق من نص صفحتين |
| PDF صوري متعدد الصفحات | `2-4` | ثلاث صفحات متتالية صحيحة؛ المصدر لم يتغير |
| PDF page-tree معطوب | `1` | رفض برسالة أن البنية غير قابلة للقراءة؛ لا مخرج |
| PDF محمي | `1` | رفض برسالة حماية؛ لا مخرج |
| غير PDF بامتداد PDF | `1` | رفض قبل التحليل؛ لا مخرج |

## الفحوص

نجح `pnpm check`، واختبارات `pdf-extract-pages` و`pdf-engine` (8/8)، وبناء الإنتاج المحلي، واختبارات Regression المركزة لـOCR وPDF→JPG وPDF→Word وQR (17/17). بقيت `pnpm test` الكاملة عند 120 نجاحًا وفشل تاريخي واحد في `file-handoff.test.ts` يتوقع أن PDF→Word ليست Ready؛ لم يعدل هذا العمل ذلك الاختبار أو PDF→Word.

## الحد

لا يتاح قبول واجهة Workspace المرئية بينما الأداة Disabled؛ حُقق مسار المتصفح الفعلي والدوال والمخرجات مباشرةً مع بقاء الحارس. لا يعني نجاح المرحلة أن الأداة Ready أو منشورة.
